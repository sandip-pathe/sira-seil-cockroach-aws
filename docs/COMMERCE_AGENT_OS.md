# Commerce Agent OS

SIRA and SEIL are persistent mission agents, not chat forms. A user supplies an outcome; the root agent plans, searches authorized sources, delegates bounded work, runs reproducible evaluations, builds inspectable artifacts, and returns only when attention or authority is actually required.

## Runtime law

**The agent acts; artifacts prove; authority gates external effects.**

- PostgreSQL owns canonical mission, event, task, artifact, experiment, checkpoint, grant, and effect state.
- The model is the adaptive control plane for planning, investigation, synthesis, ranking, and recommendation.
- Tools provide observed facts. Every meaningful conclusion carries authority, provenance, and limitations.
- Workers receive bounded tasks, budgets, tools, and no protected-effect capability.
- Experiments name fixtures, procedure, environment, success signals, replay instructions, cost, and limitations.
- The deterministic authority microkernel owns identity, approval, capability scope, idempotency, money, publishing, signing, sending, and activation.
- Temporal coordinates durable waits, retries, reconciliation, and compensation. It is not the agent's memory or reasoning engine.

## Mission loop

1. Append the user's message to the mission event stream.
2. Resume the latest immutable checkpoint and bounded world model.
3. Orient and revise the plan.
4. Use tools or bounded workers to reduce material uncertainty.
5. Persist claims, events, tasks, and evidence artifacts.
6. Continue autonomously while the budget permits and no human attention is required.
7. At a protected effect, stop with an exact proposal. The server validates human authority and issues a narrow, expiring capability grant.
8. Execute idempotently, verify provider state, and persist the result artifact.

Conversation is one projection of this state. The product UI is a mission stream with an on-demand artifact inspector; it is never a separate Decision Room, Agent Run application, or manual card-entry workflow.

## Non-negotiable boundaries

- No model can create or widen a capability grant.
- No prose-only benchmark can become verified evidence.
- No worker can approve or dispatch a protected effect.
- No credentials enter model context, artifacts, experiment specs, or logs.
- Unknown outcomes enter reconciliation; they are never blindly retried.
- Seller-private evidence is not projected into buyer context.
